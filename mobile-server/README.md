# 📱 Особенности развертывания медиакомбайна на Android (Termux)

Данный документ описывает специфику работы, сетевую архитектуру и обход системных ограничений при запуске медиа-сервера (на базе `orange-home-ui`) на смартфоне в среде **Termux** (без root-прав).

Готовые шаблоны конфигурационных файлов находятся в директории [`example/`](./example/).

---

## 🛠 Стек и актуальные версии ПО

* **Окружение:** Termux (Android sandbox)
* **Веб-сервер / Reverse Proxy:** `nginx 1.31.8`
* **Торрент-клиент:** `qBittorrent-nox v5.3.0`
* **WebDAV-сервер (стриминг на ТВ/ПК):** `rclone v1.75.2-termux`
* **Удаленный доступ:** `OpenSSH (sshd)`

---

## 🔌 Карта портов и маршрутизация

Из-за отсутствия root-прав в Android приложения не могут занимать привилегированные порты (ниже `1024`), поэтому все службы разведены по высоким портам:

| Сервис / Назначение | Внутренний адрес | Внешний доступ (LAN) | Примечание |
| :--- | :--- | :--- | :--- |
| **Web UI (`orange-home-ui`)** | `127.0.0.1:8888` | `http://<IP_СМАРТФОНА>:8888` | Главный интерфейс + Reverse Proxy для API |
| **qBittorrent WebUI** | `127.0.0.1:8889` | Через Nginx (`/api/qbittorrent/`) | Внутренний порт изменен с дефолтного `8080` |
| **WebDAV (Rclone)** | `0.0.0.0:8085` | `http://<IP_СМАРТФОНА>:8085` | Сетевая папка с фильмами для ТВ (VLC/Nova) и ПК |
| **System API** | `127.0.0.1:8095` | Через Nginx (`/api/system/`) | Мониторинг ресурсов смартфона (в разработке) |
| **SSH-сервер** | `0.0.0.0:8022` | `ssh u0_a438@<IP_СМАРТФОНА> -p 8022` | Стандартный порт SSH в Termux |
| **Внешний Jackett и TMDB** | — | Проксируются через Nginx | Вынесены на внешний сервер (`vres271.hlab.kz`) |

## ⚙️ Архитектурные особенности и решения для Android

### 1. Веб-сервер и проксирование (Nginx)
* **Путь в системе:** `$PREFIX/etc/nginx/nginx.conf` (шаблон: [`example/nginx.conf`](./example/nginx.conf)).
* **Обход ограничений:** Сервер слушает порт `8888`. Запросы к `qBittorrent` проксируются через `/api/qbittorrent/` с очисткой заголовка `Access-Control-Allow-Origin` во избежание конфликтов CORS и увеличенным таймаутом (`300s`).
* **Разгрузка смартфона:** Тяжелые задачи каталогизации (Jackett) и загрузки метаданных/постеров (TMDB) вынесены на внешний домашний сервер и прозрачно проксируются через Nginx.
* **Управление кэшем:** Файлы конфигурации интерфейса (`config.json`, `version.json`) отдаются без кэширования (`no-store`), а статика (JS, CSS, шрифты) кэшируется на 1 год.

### 2. Торрент-клиент и песочница Android (qBittorrent)
* **Путь в системе:** `~/.config/qBittorrent/qBittorrent.conf` (шаблон: [`example/qBittorrent.conf`](./example/qBittorrent.conf)).
* **Директория загрузок:** Используется внутренняя память Termux (`/data/data/com.termux/files/home/downloads`), так как работа через внешний раздел `/sdcard/` сильно режет скорость из-за FUSE-прослойки Android.
* **Автовыдача прав (`chmod`):** По умолчанию `qBittorrent` создает файлы с правами `600` (`-rw-------`), из-за чего процесс `rclone` видит папку пустой. В настройках включен триггер на добавление торрента (`OnTorrentAdded`), который сразу открывает права на чтение (`644`), позволяя смотреть кино на ТВ ещё в процессе скачивания. *(Для многофайловых раздач с подпапками требуются права `755`)*.
* **Работа за Reverse Proxy:** В конфиге отключены `CSRFProtection` и `HostHeaderValidation`, активирован параметр `ReverseProxySupportEnabled=true`.

### 3. Стриминг по WebDAV (Rclone) и автозапуск
* **Путь в системе:** `~/.bashrc` (шаблон: [`example/bashrc`](./example/bashrc)).
* **Сброс кэша при удалении:** Rclone запущен на порту `8085` без авторизации (для доверенной LAN) с флагами `--dir-cache-time 5s` и `--poll-interval 5s`. Это заставляет сервер обновлять список файлов каждые 5 секунд, чтобы удаленные торренты сразу исчезали с экрана ТВ.
* **Буферизация:** Флаг `--vfs-cache-mode minimal` обеспечивает плавное воспроизведение и перемотку тяжелых MKV-файлов (8+ ГБ) по Wi-Fi.
* **Защита от дублирования:** В Termux нет `systemd`, а `~/.bashrc` выполняется при каждом открытии вкладки или SSH-сессии. Запуск всех служб обернут в проверку `pgrep` и утилиту `nohup`.

## 🖥 Подключение сетевой папки на клиентах

### Smart TV (Android TV / Google TV)
Рекомендуется использовать плееры с нативной поддержкой WebDAV (**VLC** или **Nova Video Player**):
* **Протокол:** `HTTP` или `WebDAV`
* **Хост:** `<IP_СМАРТФОНА>` (например, `192.168.0.121`)
* **Порт:** `8085`
* **Авторизация:** Не требуется (поля логина и пароля оставить пустыми)

### Монтирование сетевого диска в Windows 10 / 11
По умолчанию Windows блокирует подключение WebDAV по незащищенному `http://` и ограничивает копирование файлов размером до 50 МБ.

1. **Настройка реестра (выполняется один раз от имени Администратора):**
   ```cmd
   reg add "HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters" /v BasicAuthLevel /t REG_DWORD /d 2 /f
   reg add "HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters" /v FileSizeLimitInBytes /t REG_DWORD /d 4294967295 /f
   net stop WebClient && net start WebClient
   ```
2. **Подключение диска:**
   * Откройте **Проводник** (`Win + E`) -> **«Этот компьютер»** -> **«Подключить сетевой диск»**.
   * Выберите букву диска (например, `Z:`) и укажите путь: `http://192.168.0.121:8085`.
   * Отметьте **«Восстанавливать при входе в систему»**.
   * *Быстрое управление из консоли:* `net use Z: http://192.168.0.121:8085` (подключить) / `net use Z: /delete` (отключить).

## 💡 Важные нюансы эксплуатации на Android
* **Энергосбережение (Doze Mode):** В настройках батареи Android для приложения Termux должен быть выбран режим **«Без ограничений»**.
* **Блокировка сна (Wakelock):** В шторке уведомлений Android для процесса Termux должна быть активна кнопка **Acquire wakelock**, чтобы система не отключала Wi-Fi и фоновые службы при погашенном экране.
