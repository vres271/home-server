# 📱 Развертывание медиакомбайна на Android (Termux)

Данный документ описывает пошаговую установку на чистый **Termux** (без root-прав), сетевую архитектуру, обход ограничений песочницы Android, оптимизацию под флеш-память смартфона и правила эксплуатации медиа-сервера (на базе `orange-home-ui`).

Готовые шаблоны конфигурационных файлов находятся в директории [`example/`](./example/).

---

## 🛠 Стек и актуальные версии ПО

* **Окружение:** Termux (устанавливать только из **F-Droid** или **GitHub**, версия из Google Play устарела)
* **Веб-сервер / Reverse Proxy:** `nginx 1.31.8`
* **Торрент-клиент:** `qBittorrent-nox v5.3.0` (`libtorrent 2.0`)
* **WebDAV-сервер (стриминг на ТВ/ПК):** `rclone v1.75.2-termux`
* **Удаленный доступ:** `OpenSSH (sshd)`

---

## 🚀 Установка с нуля на чистый Termux

### 1. Базовая настройка и обновление пакетов
После первого запуска Termux обновите репозитории, базовые пакеты и создайте директорию для загрузок во внутренней памяти терминала:

```bash
pkg update && pkg upgrade -y
mkdir -p ~/downloads
```

### 2. Установка необходимых пакетов
Установите веб-сервер, торрент-клиент, WebDAV-сервер и SSH для удобного управления с ПК:

```bash
pkg install nginx qbittorrent-nox rclone openssh -y
```

### 3. Настройка SSH-доступа (для управления с ПК)
Задайте пароль для текущего пользователя Termux (узнать имя пользователя можно командой `whoami`, например `u0_a438`) и узнайте локальный IP-адрес смартфона:

```bash
passwd
whoami
ifconfig wlan0 | grep inet
```
*Подключение с ПК выполняется по нестандартному порту `8022`: `ssh u0_a438@<IP_СМАРТФОНА> -p 8022`.*

### 4. Развертывание конфигураций
Скопируйте шаблоны из папки [`example/`](./example/) в системные директории Termux (предварительно разместив файлы фронтенда `orange-home-ui` в `~/orange-home-ui`):

```bash
# 1. Конфигурация Nginx
cp example/nginx.conf $PREFIX/etc/nginx/nginx.conf

# 2. Конфигурация qBittorrent (заранее создаем директорию настроек)
mkdir -p ~/.config/qBittorrent
cp example/qBittorrent.conf ~/.config/qBittorrent/qBittorrent.conf

# 3. Автозапуск и алиасы
cp example/bashrc ~/.bashrc
source ~/.bashrc
```

## 🔌 Карта портов и маршрутизация

Из-за отсутствия root-прав в Android приложения не могут занимать привилегированные порты (ниже `1024`), поэтому все службы разведены по высоким портам:

| Сервис / Назначение | Внутренний адрес | Внешний доступ (LAN) | Примечание |
| :--- | :--- | :--- | :--- |
| **Web UI (`orange-home-ui`)** | `127.0.0.1:8888` | `http://<IP_СМАРТФОНА>:8888` | Главный интерфейс + Reverse Proxy для API |
| **qBittorrent WebUI** | `127.0.0.1:8889` | Через Nginx (`/api/qbittorrent/`) | Внутренний порт изменен с дефолтного `8080` |
| **WebDAV (Rclone)** | `0.0.0.0:8085` | `http://<IP_СМАРТФОНА>:8085` | Сетевая папка с фильмами для ТВ (VLC/Nova) и ПК |
| **System API** | `127.0.0.1:8095` | Через Nginx (`/api/system/`) | Мониторинг ресурсов смартфона (в разработке) |
| **SSH-сервер** | `0.0.0.0:8022` | `ssh u0_a438@<IP_СМАРТФОНА> -p 8022` | Стандартный порт SSH в Termux |
| **Внешний Jackett и TMDB** | — | Проксируются через Nginx | Вынесены на внешний сервер (`vres271.hlab.kz`) |

## ⚙️ Архитектурные особенности и решения для Android

### 1. Веб-сервер и проксирование (Nginx)
* **Путь в системе:** `$PREFIX/etc/nginx/nginx.conf` (шаблон: [`example/nginx.conf`](./example/nginx.conf)).
* **Обход ограничений:** Сервер слушает порт `8888`. Запросы к `qBittorrent` проксируются через `/api/qbittorrent/` с очисткой заголовка `Access-Control-Allow-Origin` во избежание конфликтов CORS и увеличенным таймаутом (`300s`).
* **Разгрузка смартфона:** Тяжелые задачи каталогизации (Jackett) и загрузки метаданных/постеров (TMDB) вынесены на внешний домашний сервер и прозрачно проксируются через Nginx.
* **Управление кэшем:** Файлы конфигурации интерфейса (`config.json`, `version.json`) отдаются без кэширования (`no-store`), а статика (JS, CSS, шрифты) кэшируется на 1 год.

### 2. Торрент-клиент и защита флеш-памяти (qBittorrent)
* **Путь в системе:** `~/.config/qBittorrent/qBittorrent.conf` (шаблон: [`example/qBittorrent.conf`](./example/qBittorrent.conf)).
* **Директория загрузок:** Используется внутренняя память Termux (`/data/data/com.termux/files/home/downloads`), так как работа через внешний раздел `/sdcard/` сильно режет скорость из-за FUSE-прослойки Android.
* **Автовыдача прав (`chmod`):** По умолчанию `qBittorrent` создает файлы с правами `600` (`-rw-------`), из-за чего процесс `rclone` видит папку пустой. В настройках включен триггер на добавление торрента (`OnTorrentAdded`), который сразу открывает права на чтение (`644`), позволяя смотреть кино на ТВ ещё в процессе скачивания. *(Для многофайловых раздач с подпапками требуются права `755`)*.
  * *Важно:* В WebUI qBittorrent v5.3.0 присутствует баг экранирования кавычек при сохранении настроек через браузер — не нажимайте «Сохранить» в веб-интерфейсе, правки вносите только напрямую в файл `qBittorrent.conf` при остановленном клиенте.
* **Защита памяти UFS/eMMC от износа (`libtorrent 2.0`):**
  * **Очередь диска в ОЗУ (`DiskQueueSize=262144`):** Накапливает до 256 МБ данных в оперативной памяти перед сбросом на накопитель.
  * **Склейка блоков и кэш ОС (`CoalesceReadWrite=true`, `EnableOSCache`):** Объединяет мелкие соседние записи в крупные последовательные блоки и задействует системный page cache ядра.
  * **Снижение нагрузки на контроллер (`AsyncIOThreadsCount=4`, `Preallocation=true`):** Уменьшает конкуренцию потоков записи и заранее выделяет место под файл, исключая фрагментацию.
* **«Тихое сидирование» и лимиты сети:**
  * Скорость отдачи ограничена до **100 КиБ/с** (`GlobalUPSpeedLimit=100`), скачивание без лимита (`0`).
  * Сетевые соединения ограничены до **100** общих и **40** на торрент, слоты отдачи — до **2** общих и **1** на торрент, чтобы не перегревать Wi-Fi-модуль и CPU телефона.
  * Автоматическая остановка раздачи при достижении рейтинга **1.05** (`MaxRatio=1.05`, `ShareLimitAction=Stop`) исключает бан за hit-and-run и лишнее чтение с флешки.
* **Работа за Reverse Proxy:** В конфиге отключены `CSRFProtection` и `HostHeaderValidation`, активирован параметр `ReverseProxySupportEnabled=true`.

### 3. Стриминг по WebDAV (Rclone)
* **Сброс кэша при удалении:** Rclone запущен на порту `8085` без авторизации (для доверенной LAN) с флагами `--dir-cache-time 5s` и `--poll-interval 5s`. Это заставляет сервер обновлять список файлов каждые 5 секунд, чтобы удаленные торренты сразу исчезали с экрана ТВ.
* **Буферизация:** Флаг `--vfs-cache-mode minimal` обеспечивает плавное воспроизведение и перемотку тяжелых MKV-файлов (8+ ГБ) по Wi-Fi.

## 🔄 Автозапуск и управление службами (`~/.bashrc`)

В Termux отсутствует полноценный `systemd`, а файл `~/.bashrc` выполняется при каждом открытии новой вкладки или подключении по SSH. 

* **Защита от дублирования:** Запуск каждой службы обернут в проверку `pgrep`, чтобы при открытии новых сессий не возникали ошибки занятых портов, а `nohup` отвязывает процесс Rclone от окна терминала.
* **Безопасная остановка (`stopmedia`):** Принудительное закрытие Termux через настройки Android («Остановить») обрывает `qBittorrent` без сохранения прогресса закачек, что ведет к долгой перехешировке файлов. Для корректного завершения в `~/.bashrc` добавлен специальный алиас `stopmedia`.

### Актуальное содержимое `~/.bashrc` (шаблон: [`example/bashrc`](./example/bashrc)):

```bash
# Автозапуск SSH-сервера
sshd

# Автозапуск сетевой папки (WebDAV) для просмотра фильмов на ТВ/ПК
pgrep -x rclone >/dev/null || nohup rclone serve webdav /data/data/com.termux/files/home/downloads --addr 0.0.0.0:8085 --vfs-cache-mode minimal --dir-cache-time 5s --poll-interval 5s >/dev/null 2>&1 &

# Автозапуск торрент-клиента и веб-сервера
pgrep -x qbittorrent-nox >/dev/null || qbittorrent-nox -d
pgrep -x nginx >/dev/null || nginx

# Алиас для безопасной остановки всех служб с проверкой выгрузки из памяти
alias stopmedia='pkill -TERM qbittorrent-nox; nginx -s quit 2>/dev/null; pkill -TERM rclone; sleep 2; pgrep -a "rclone|qbittorrent|nginx" && echo "⚠️ Что-то ещё завершается, подождите..." || echo "✅ Все службы чисто остановлены, Termux можно закрывать"'
```

## 🖥 Подключение сетевой папки на клиентах

### Smart TV (Android TV / Google TV)
Рекомендуется использовать плееры с нативной поддержкой WebDAV (**VLC** или **Nova Video Player**):
* **Протокол:** `HTTP` или `WebDAV`
* **Хост:** `<IP_СМАРТФОНА>` (например, `192.168.0.121`)
* **Порт:** `8085`
* **Авторизация:** Не требуется (поля логина и пароля оставить пустыми)

### Монтирование сетевого диска в Windows 10 / 11
По умолчанию Windows блокирует подключение WebDAV по незащищенному `http://` и ограничивает копирование файлов размером до 50 МБ.

1. **Настройка реестра (выполняется один раз от имени Администратора):**
   ```cmd
   reg add "HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters" /v BasicAuthLevel /t REG_DWORD /d 2 /f
   reg add "HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters" /v FileSizeLimitInBytes /t REG_DWORD /d 4294967295 /f
   net stop WebClient && net start WebClient
   ```
2. **Подключение диска:**
   * Откройте **Проводник** (`Win + E`) -> **«Этот компьютер»** -> **«Подключить сетевой диск»**.
   * Выберите букву диска (например, `Z:`) и укажите путь: `http://192.168.0.121:8085`.
   * Отметьте **«Восстанавливать при входе в систему»**.
   * *Быстрое управление из консоли:* `net use Z: http://192.168.0.121:8085` (подключить) / `net use Z: /delete` (отключить).

## 💡 Регламент эксплуатации на Android

1. **Энергосбережение (Doze Mode):** В настройках батареи Android для приложения Termux должен быть выбран режим **«Без ограничений»**.
Используйте код с осторожностью.
2. Блокировка сна (Wakelock): В шторке уведомлений Android для процесса Termux должна быть активна кнопка Acquire wakelock, чтобы система не отключала Wi-Fi и фоновые службы при погашенном экране.
3. Порядок полного выключения сервера:
	• Введите в консоли Termux (или по SSH) команду stopmedia и дождитесь сообщения ✅ Все службы чисто остановлены, Termux можно закрывать.
	• Опустите шторку уведомлений на смартфоне и нажмите кнопку Exit в уведомлении Termux для выгрузки графической оболочки.
